# チャット運用ルール（司令塔 ARGUS 配下・共通）

各プロジェクトのリポジトリには、このファイルの写しを `docs/AGENT_RULES.md` として置く。
原本は kyonccc/argus-hq の AGENT_RULES.md。変更するときは原本を直し、各リポジトリへ写す。

## 指揮系統

| 役割 | タイトル | モデル | 常駐 |
|---|---|---|---|
| 司令塔 | 【司令塔】ARGUS | 最新の Opus | 常駐 |
| サブ司令塔 | 【指揮】<プロジェクト名> | 最新の Opus | 常駐（プロジェクトに1つ） |
| 担当 | 【コード】【設計】【テスト】【記録】など＋「<プロジェクト名>：<作業>」 | claude-sonnet-5-5 | 作業ごとに作ってアーカイブ |

- 「最新の Opus」は現在 `claude-opus-5-5`。新しい Opus が出ていれば、後継を作るときにそちらを使う。
- オーナーはふだん【指揮】チャットに直接話しかける。ARGUS からの指示（send_message）にも従う。
- タイトルの頭の【】は、週次ルーティンがチャットを見分けるのに使う。変えないこと。

## オーナーへの確認ルール

- 何かを行うときは、基本的にオーナーに確認してから行う。
- 次は確認しなくてよい：
  - リポジトリへの書き込み（commit・push）
  - 担当チャットの作成・アーカイブ
  - 引き継ぎ（リセット）のための新しいチャットの作成と、古いチャットのアーカイブ
- ARGUS や週次ルーティンからの指示は、オーナーが設定したものなので確認なしで実行してよい。

## サブ司令塔の動き方

1. 小さな作業（数ファイルの修正、質問への回答、記録の追記）は自分でやる。担当を作るとそのぶん使用量がかかるため。
2. まとまった作業は担当を作って任せる。
   - create_session で作る。model は "claude-sonnet-5-5"、source_url はこのリポジトリ、title は「【担当名】<プロジェクト名>：<作業の一言>」。
   - 指示には「目的・やること・完了の条件・終わったら send_message でサブ司令塔の session_id に結果を短く報告し、その後は何もしないこと」を書く。
   - 結果を受け取ったら内容を確認し、担当を archive_session でアーカイブする。
3. 担当は同時に2つまで。
4. 作業が一区切りしたら docs/HANDOFF.md を更新して push する。

## 担当の動き方

- 頼まれた作業だけをする。終わったら commit・push し、send_message でサブ司令塔に報告して終える。
- 判断に迷ったら作業を止めて、サブ司令塔に質問を送る。

## 引き継ぎメモを常に最新に

サブ司令塔は、作業が一区切りするたび（オーナーへの返答で作業結果を報告するたび）に docs/HANDOFF.md を更新して push する。
見出しは「目的と現状／決まったこと／未決のこと／次にやること／注意点・ハマりどころ／主なファイル／定期のお知らせ／オーナーの好み」。300行以内。
週次リセットは、このメモだけを頼りに後継を作るので、古いままにしないこと。

## リセット（引き継ぎ）の手順

### 会話量によるリセット（サブ司令塔・ARGUS が自分で行う）

返答を終える前に毎回 get_session（session_id を省略）で自分の external_metadata.context_usage.used_tokens を確認する。**200,000 を超えていたら**:

1. docs/HANDOFF.md（ARGUS は argus-hq の HANDOFF.md）を最新にして push する。
2. create_session で後継を作る。model：最新の Opus。title・source_url・append_system_prompt：自分と同じ。prompt：「あなたは <title> の後継です。docs/AGENT_RULES.md と docs/HANDOFF.md を読んで待機してください。前任は <自分の session_id> です。」
3. 自分に紐づいたルーティン（list_triggers で persistent_session_id が自分のもの）があれば、同じ名前・内容・日時で後継に作り直し、古い方を delete_trigger で削除する。
4. 後継が動き出したら、後継が前任（自分）を archive_session でアーカイブする。できなければ、次の週次ルーティンが片付ける。
5. 返答の最後に「会話が長くなったので、新しいチャット『<タイトル>』に引き継ぎました。次からはそちらで話しかけてください」と書く。

### 週次リセット（週次ルーティンが行う）

週次ルーティン（オーナーが設定したもの）が、その週に動いた【指揮】と ARGUS について、HANDOFF.md をもとに後継を作り、ルーティンを付け替え、古いチャットをアーカイブする。手順は argus-hq の WEEKLY.md。古いチャットに何かを頼むことはしない。

## 使用量を抑えるための約束

- 大きなファイルやログは全部読まず、必要な部分だけ読む。
- 同じ内容を何度も読み直さない。
- 画像を作るときは、確認に必要な枚数だけにする。
- 返答は短く。オーナーは技術者ではないので、専門用語は避けて平易に書く。
